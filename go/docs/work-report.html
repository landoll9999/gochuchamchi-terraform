  • 앱·데이터RDS MariaDB — Secrets Manager 자동 비밀번호 관리(manage_master_user_password), schema.sql 자동 적용 프로비저너

2026-08-03 full-HA·보안 강화 일괄 적용

테마: 격차분석 이행일 — 경계 방어부터 DR까지 13개 파일 일괄 구축

  • L1 경계CloudFront + WAFv2(관리형 룰 3종 + rate limit) + us-east-1 ACM + ALB SG를 CloudFront prefix list로 잠금 (edge.tf, 2단계 apply)
  • L2 네트워크DB 서브넷 커스텀 NACL + VPC 인터페이스 엔드포인트 7종(ECR/SSM/Secrets/Logs — NAT 무관 경로)
  • 암호화KMS CMK 2종(로그/데이터) + 키 정책 — 로그 버킷 SSE-KMS
  • IAMAccess Analyzer + MFA 강제 그룹 + Region Guard / GitHub Actions OIDC(sub 조건 — 액세스 키 제로)
  • 탐지GuardDuty 확장(EKS 감사·S3·EBS 말웨어·15분 주기) + VPC Flow Logs→S3+Athena(포트스캔/유출 조사 쿼리 3종)
  • K8sKyverno(restricted Audit) + LimitRange/ResourceQuota + PSA 라벨 — 컨테이너 보안 3레이어
  • HANAT AZ별 2대(moved 무중단 인수) + 도쿄 DR(AWS Backup 크로스리전 + S3 CRR)
  • 비용Budgets + Cost Anomaly Detection / SNS 이메일 백업 채널
  • 설계 변경AWS Config 전용 버킷 분리 — 5라운드 수사 끝 "증적 등급별 통제 분리" 결정
  • 복구재구축 후 사이트 복구 4건 + rds-schema-init.tf 실패 표면화 개선 + runbook 전면 개편

2026-08-04 제로트러스트 · 복원 · 자동화

테마: 최다 산출일 — DB 제로트러스트 전환, 장애 복구, 소실 복원 병합, 재발 방지 자동화까지

① 제로트러스트 DB 하드닝 (2026-08-04.md)
  • 최소권한앱 전용 DB 계정 gochuchamchi_app(DML만 + REQUIRE SSL) — 배스천 런타임 생성/주입으로 앱 DB 비밀번호가 tfstate에 안 남는 구조
  • 암호화RDS require_secure_transport=1(전송 TLS 강제) + MARIADB_AUDIT_PLUGIN→CloudWatch / Redis replication_group 전환 — TLS + AUTH
  • 축소배스천·앱 IAM rds!* 와일드카드 → 정확한 ARN 2개, 배스천 K8s 권한 ClusterAdmin → 네임스페이스 Edit, DB/캐시 SG egress 제거
  • 백로그B1~B6 이행 — SG 참조 축소·SSH 완전 제거·ESO 도입(PAT state 이관)·ArgoCD 비번 코드화·NetworkPolicy·GuardDuty
② 장애 복구 + 복구 후 재점검 (2026-08-04-incident-and-review.md)
  • 복구"반쪽 배포" DB 전면 500 → 장애 5건 연쇄 해결, /api/health 500→302 외부 검증
  • 점검하드코딩 인벤토리(🔴 AMI ID·backend 계정 종속 / 🟡 의도적 / 🟢 정답 구분) + 보안 재점검(IAM "*" 전수 확인, Grafana 비밀번호 state 평문 적발→제거, .gitignore 보강)
③ 알림 허브 + full-HA 복원 병합
  • 알림SNS 허브 — EventBridge→SNS 팬아웃(Discord+이메일) + SQS DLQ + 자기 감시 알람 (cloudwatch-notifications/sns.tf)
  • 복원8/3 full-HA 13개 파일 소실 발견 → fin 사본에서 복원 + 제로트러스트와 3-way 병합 (8/4 코드 우선 원칙, validate 통과, 파괴 항목은 재구축 사이클로 보류)
  • 정리apply 오류 2건 해결(Cost Anomaly import, Inspector2 untaint) + waf-cdn 중복 정리 → WAF/CloudFront edge 로그(edge-logs.tf)로 재구성
④ 재발 방지 자동화 3종 (2026-08-04-automation.md)
  • 자동화배포 계약 — contract.tf가 terraform↔gitops 인터페이스 선언, verify-contract.ps1이 정적+라이브 양방향 검증 (잔재 파일 적발 포함)
  • 자동화스모크 테스트 — apply 후 12개 항목 자동 점검(파드·DNS·포트·ALB·HTTP), 실패마다 다음 행동 출력
  • 자동화수동 변경 감지 — CloudTrail 콘솔 세션/IAM 변경/루트 사용 → SNS 허브 실시간 통보

총평 — 8일의 궤적

구축(7/27~28) → 자동화(7/29) → 관측(7/30) → 설계(7/31) → 강화(8/3) → 제로트러스트·자가치유(8/4) 순서로 계층을 쌓았다. 특히 후반부의 전환이 뚜렷하다: 초반에는 "만들고 고치는" 날들이었다면, 7/31부터는 함정을 apply 전에 설계로 회피하기 시작했고, 8/4에는 사람의 체크리스트가 두 번 실패한 지점(반쪽 배포, ECR 비움)을 계약 검증·스모크 테스트·드리프트 감지라는 강제 장치로 바꿨다. 남은 큰 덩어리는 CloudFront 2차 apply 활성화, 재구축 사이클의 파괴적 보안 항목 (RDS/EFS CMK, Object Lock), 이미지 태그 자동화(write PAT read-only 강등)다.
