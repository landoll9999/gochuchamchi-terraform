## 1. ECR state 분리 — 계획 수립 (미실행)

### 작업 목적

`terraform/ecr.tf`의 `aws_ecr_repository`에 `force_delete = true`가 걸려 있어, `terraform destroy` 시 **ECR 저장소가 푸시된 이미지까지 통째로 삭제**됩니다.

재구축하면 ECR이 빈 상태로 다시 생성되는데 GitOps 저장소의 Deployment는 여전히 옛 이미지 태그를 참조하므로, 파드가 `ImagePullBackOff`에 빠지고 ALB가 503을 반환합니다. **2026-07-31 당일 실제로 발생**했고, 그때마다 `gochuchamchi-spring`의 CI를 수동으로 다시 돌려야 했습니다.

ECR을 별도 state로 떼어내면 메인 인프라를 destroy/apply해도 이미지가 살아남아 재구축 직후 파드가 바로 뜹니다.

### 설계에서 주의 깊게 다룬 부분

- **실행 순서 역전 시 파괴 위험** — `ecr.tf`를 지운 상태에서 메인 apply를 돌리면 terraform이 ECR을 파괴하고 `force_delete = true`라 이미지까지 전부 삭제됩니다. 매뉴얼 6장에 경고 블록으로 강조돼 있습니다
- **`prevent_destroy`** — 분리한 state에는 `lifecycle { prevent_destroy = true }`를 걸어 실수 방지
- **`terraform state rm`은 AWS 리소스를 건드리지 않음** — terraform이 잊을 뿐이라는 점을 4단계에 명시
- **CI 역할 ARN 불변** — 역할 이름이 고정이라 ARN이 안 바뀌므로 GitHub Actions 워크플로 수정 불필요
- **state 백업의 민감값** — `terraform state pull` 결과에 RDS 비밀번호가 들어있어 git 커밋 금지 + 작업 후 삭제 명시
