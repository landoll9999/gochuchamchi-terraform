--------------------------------------------------------------------------------
1. 왜 하는가
--------------------------------------------------------------------------------

terraform/ecr.tf 의 aws_ecr_repository 에는 force_delete = true 가 걸려 있다.
따라서 terraform destroy 를 하면 ECR 저장소가 푸시된 이미지까지 통째로 삭제된다.

재구축 후에는 ECR 이 빈 상태로 다시 생성되는데, GitOps 저장소의 Deployment 는
여전히 예전 이미지 태그를 참조하므로 Pod 가 ImagePullBackOff 에 빠지고
ALB 가 503 을 반환한다. (2026-07-31 실제 발생)

이때마다 gochuchamchi-spring 저장소의 CI 를 수동으로 다시 돌려야 한다.

ECR 을 별도 state 로 분리하면 메인 인프라를 destroy/apply 해도 이미지가 살아남아
재구축 직후 Pod 가 바로 뜬다.

================================ go/ecr/ecr.tf
# =============================================================================
# ECR — 컨테이너 이미지 레지스트리 + GitHub Actions CI push 권한
#
# ../terraform 과 state 를 분리한 이유:
#   메인 인프라를 destroy 하면 force_delete 로 이미지가 전부 삭제되어, 재구축 후
#   GitOps 매니페스트가 가리키는 태그를 못 찾아 Pod 가 ImagePullBackOff 에 빠진다.
#   여기로 떼어내면 메인을 destroy/apply 해도 이미지가 살아남는다.
#
# ※ 메인(../terraform)보다 먼저 apply 해야 한다.
#    메인의 ecr-data.tf 가 data source 로 이 저장소를 조회하기 때문.
# =============================================================================

resource "aws_ecr_repository" "gochuchamchi" {
  name                 = "gochuchamchi"
  image_tag_mutability = "MUTABLE" # CI/Image Updater가 latest 태그를 계속 덮어씀

  # 이 디렉토리는 destroy 대상이 아니지만, 만약 destroy 하게 되면 이미지가 남아
  # 있어도 지워지도록 둔다. 실수 방지는 아래 prevent_destroy 가 담당.
  force_delete = true

  # 이 state 를 분리한 목적 자체가 이미지 보존이므로 실수로 지우는 것을 막는다.
  # 정말 삭제해야 한다면 이 블록을 먼저 지우고 destroy 할 것.
  lifecycle {
    prevent_destroy = true
  }

  image_scanning_configuration {
    scan_on_push = true
  }
}

resource "aws_ecr_lifecycle_policy" "gochuchamchi" {
  repository = aws_ecr_repository.gochuchamchi.name

  policy = jsonencode({
    rules = [{
      rulePriority = 1
      description  = "최근 10개 이미지만 유지, 나머지는 자동 만료"
      selection = {
        tagStatus   = "any"
        countType   = "imageCountMoreThan"
        countNumber = 10
      }
      action = { type = "expire" }
    }]
  })
}

# ---------------------------------------------------------------------------
# GitHub Actions(gochuchamchi-spring 저장소)가 OIDC로 AWS를 assume해서 ECR에
# push. 액세스키를 GitHub Secret에 저장할 필요가 없어 Docker Hub 방식(계정+토큰)
# 보다 안전함.
# ---------------------------------------------------------------------------
data "tls_certificate" "github_actions" {
  url = "https://token.actions.githubusercontent.com/.well-known/openid-configuration"
}

resource "aws_iam_openid_connect_provider" "github_actions" {
  url             = "https://token.actions.githubusercontent.com"
  client_id_list  = ["sts.amazonaws.com"]
  thumbprint_list = [data.tls_certificate.github_actions.certificates[0].sha1_fingerprint]
}

resource "aws_iam_role" "github_actions_ecr_push" {
  name = "gochuchamchi-github-actions-ecr-push"

  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect    = "Allow"
      Principal = { Federated = aws_iam_openid_connect_provider.github_actions.arn }
      Action    = "sts:AssumeRoleWithWebIdentity"
      Condition = {
        StringEquals = {
          "token.actions.githubusercontent.com:aud" = "sts.amazonaws.com"
        }
        # main 브랜치 push(=CI 워크플로 트리거 조건)에서만 assume 가능하도록 제한
        StringLike = {
          "token.actions.githubusercontent.com:sub" = "repo:${var.github_owner}/gochuchamchi-spring:ref:refs/heads/main"
        }
      }
    }]
  })
}

resource "aws_iam_role_policy" "github_actions_ecr_push" {
  name = "ecr-push"
  role = aws_iam_role.github_actions_ecr_push.id

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [
      {
        Sid      = "EcrAuth"
        Effect   = "Allow"
        Action   = "ecr:GetAuthorizationToken"
        Resource = "*"
      },
      {
        Sid    = "EcrPush"
        Effect = "Allow"
        Action = [
          "ecr:BatchCheckLayerAvailability",
          "ecr:GetDownloadUrlForLayer",
          "ecr:BatchGetImage",
          "ecr:PutImage",
          "ecr:InitiateLayerUpload",
          "ecr:UploadLayerPart",
          "ecr:CompleteLayerUpload",
        ]
        Resource = aws_ecr_repository.gochuchamchi.arn
      }
    ]
  })
}

output "ecr_repository_url" {
  value       = aws_ecr_repository.gochuchamchi.repository_url
  description = "gochuchamchi-gitops의 이미지 참조와 gochuchamchi-spring CI 워크플로의 push 대상으로 사용"
}

output "github_actions_ecr_role_arn" {
  value       = aws_iam_role.github_actions_ecr_push.arn
  description = "gochuchamchi-spring CI 워크플로의 aws-actions/configure-aws-credentials role-to-assume 값으로 사용"
}

[1단계] 새 디렉토리와 파일 생성
  4장의 파일 5개를 만든다. (backend / providers / variables / ecr / imports)

[2단계] 새 state 초기화
  cd C:\terraform\go\go\ecr
  $env:AWS_PROFILE = "admin"
  terraform init

[3단계] import 실행
  terraform plan

  → "5 to import, 0 to add, 0 to change, 0 to destroy" 여야 한다.
    to add / to destroy 가 0 이 아니면 여기서 멈추고 원인을 확인할 것.
    (OIDC thumbprint 는 값이 갱신되어 to change 1 이 나올 수 있으며 무해하다)

  terraform apply

[4단계] 메인 state 에서 추적 해제
  ※ state rm 은 AWS 리소스를 건드리지 않는다. Terraform 이 잊을 뿐이다.

  cd C:\terraform\go\go\terraform
  terraform state rm aws_ecr_repository.gochuchamchi
  terraform state rm aws_ecr_lifecycle_policy.gochuchamchi
  terraform state rm aws_iam_openid_connect_provider.github_actions
  terraform state rm aws_iam_role.github_actions_ecr_push
  terraform state rm aws_iam_role_policy.github_actions_ecr_push

[5단계] 메인 파일 정리
  - go/terraform/ecr.tf 삭제
  - go/terraform/ecr-data.tf 생성 (4장 참고)
  - go/terraform/argocd.tf 수정 (5장 참고)

[6단계] 임시 파일 삭제
  - go/ecr/imports.tf 삭제

[7단계] 검증
  cd C:\terraform\go\go\terraform
  terraform plan

  → "No changes" 여야 한다.
    ECR 관련 create/destroy 가 하나라도 보이면 8장(문제 대응)으로.

8. 문제 대응 / 되돌리기
--------------------------------------------------------------------------------

[3단계에서 to add 나 to destroy 가 보인다]
  import id 가 틀렸을 가능성이 높다. apply 하지 말고 확인할 것.
  OIDC provider ARN 은 계정 ID 가 맞는지 확인:
    aws iam list-open-id-connect-providers --profile admin

[4단계 이후 되돌리고 싶다]
  메인 state 로 다시 import 하면 된다. ecr.tf 를 복원한 뒤:
    cd C:\terraform\go\go\terraform
    terraform import aws_ecr_repository.gochuchamchi gochuchamchi
    terraform import aws_ecr_lifecycle_policy.gochuchamchi gochuchamchi
    terraform import aws_iam_openid_connect_provider.github_actions `
      arn:aws:iam::307223751140:oidc-provider/token.actions.githubusercontent.com
    terraform import aws_iam_role.github_actions_ecr_push gochuchamchi-github-actions-ecr-push
    terraform import aws_iam_role_policy.github_actions_ecr_push `
      gochuchamchi-github-actions-ecr-push:ecr-push
  그리고 go/ecr 의 state 를 비운다 (또는 S3 에서 ecr/terraform.tfstate 삭제).

[7단계에서 ECR 을 destroy 하려 한다]
  ecr-data.tf 가 없거나 argocd.tf 가 아직 resource 를 참조하고 있다.
  절대 apply 하지 말고 5장을 다시 확인할 것.

[state lock 이 걸렸다]
  terraform force-unlock <LOCK_ID>


--------------------------------------------------------------------------------
9. 이후 운영 방식 변경점
--------------------------------------------------------------------------------

apply 순서 (신규 구축 시)
  1) cd go/ecr        && terraform apply
  2) cd go/terraform  && terraform apply
  3) cd go/discord-notifications && terraform apply   (기존과 동일)

destroy 순서
  1) cd go/terraform && terraform destroy
  2) go/ecr 는 destroy 하지 않는다 (이미지 보존이 목적).
     prevent_destroy 때문에 시도해도 막힌다.

재구축 후
  ECR 이미지가 살아있으므로 CI 재실행 없이 Pod 가 바로 뜬다.
  단, GitOps 매니페스트의 태그가 ECR 라이프사이클 정책(최근 10개 유지)으로
  만료된 경우에는 여전히 CI 재실행이 필요하다.

메인 apply 시 주의
  go/ecr 를 apply 하지 않은 상태에서 메인을 apply 하면
  data.aws_ecr_repository 조회 실패로 plan 단계에서 멈춘다. 정상 동작이다.
